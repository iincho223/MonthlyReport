# Feature Specification: 月報詳細・フィードバック

**Feature Branch**: `004-report-detail-feedback`

**Created**: 2026-08-22

**Status**: Draft

**Input**: User description: "月報詳細画面とフィードバック（回答）機能。詳細画面では月報の全項目（対象月・所属・営業情報・残業見込み・コンディション7項目・コメント）と回答内容を表示する。作成者本人には編集ボタン、作成者本人またはOMロールには削除ボタンを表示する。TL以上のロールが他者（自分以外）の月報を開いた場合のみ回答入力欄が表示され、回答を登録・公開できる。回答は自分自身が作成した月報には登録できない。回答が登録されると回答者のロール・氏名・登録日時とともに全ロールに表示される。フィードバックは報告月の翌月5日まで可能とする。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 月報の詳細を確認する (Priority: P1)

閲覧権限を持つユーザーが、月報の全項目と回答内容を1画面で確認できる。

**Why this priority**: 一覧から個別月報を確認する基本操作であり、これがなければ編集・削除・フィードバックのいずれも成立しない。

**Independent Test**: 閲覧可能な月報を開き、対象月・所属・営業情報・残業見込み・コンディション7項目・コメント・回答内容が表示されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** 閲覧可能な月報が存在する、**When** その月報の詳細を開く、**Then** 対象月・所属（営業所・チーム）・営業情報・来月/今月残業見込み（時間・理由）・コンディション7項目・コメントが表示される。
2. **Given** 回答が未登録の月報の詳細を開いている、**When** 回答表示欄を確認する、**Then** 回答が未登録であることが分かる状態で表示される。
3. **Given** 回答が登録済みの月報の詳細を開いている、**When** 回答表示欄を確認する、**Then** 回答内容・回答者のロール・氏名・回答日時が表示される。

---

### User Story 2 - 自分の月報を編集・削除する導線を得る (Priority: P2)

作成者本人が自分の月報の詳細画面から編集操作へ、作成者本人またはOMロールのユーザーが削除操作へ進める。

**Why this priority**: 詳細画面から編集・削除機能（別仕様）への入口を提供するものであり、詳細表示（P1）が前提となるため次点の優先度とする。

**Independent Test**: 作成者本人で自分の月報詳細を開き編集ボタンが表示されること、OMロールで他者の月報詳細を開き削除ボタンが表示されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** 作成者本人が自分の月報詳細を開いている、**When** 画面を確認する、**Then** 編集ボタンが表示されている。
2. **Given** 作成者本人以外が他者の月報詳細を開いている、**When** 画面を確認する、**Then** 編集ボタンは表示されない。
3. **Given** 作成者本人またはOMロールのユーザーが月報詳細を開いている、**When** 画面を確認する、**Then** 削除ボタンが表示されている。
4. **Given** 作成者本人でもOMロールでもないユーザーが他者の月報詳細を開いている、**When** 画面を確認する、**Then** 削除ボタンは表示されない。

---

### User Story 3 - 他者の月報にフィードバックする (Priority: P1)

TL以上のロールを持つユーザーが、自分以外が作成した月報に対してコメント（回答）を登録・公開する。

**Why this priority**: フィードバックは月報運用の主要な業務価値（上長からの対応・助言）であり、詳細表示と並ぶ本機能の中核目的のためP1とする。

**Independent Test**: TL以上のロールのユーザーが他者の月報を開き、回答を入力して登録することで、回答が全ロールに表示される状態になることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** TL以上のロールのユーザーが自分以外の作成者による月報の詳細を開いている、**When** 画面を確認する、**Then** 回答入力欄が表示されている。
2. **Given** TL以上のロールのユーザーが自分自身が作成した月報の詳細を開いている、**When** 画面を確認する、**Then** 回答入力欄は表示されない。
3. **Given** TL未満のロール（TM/NG）のユーザーが月報詳細を開いている、**When** 画面を確認する、**Then** 回答入力欄は表示されない。
4. **Given** 回答入力欄に内容を入力したTL以上のユーザーが、**When** 回答公開ボタンを押す、**Then** 回答が登録され、回答者のロール・氏名・登録日時とともに全ロールから閲覧可能になる。
5. **Given** 報告月の翌月5日を過ぎた月報が存在する、**When** TL以上のユーザーが回答公開を試みる、**Then** システムは回答の登録を拒否する。

### Edge Cases

- すでに回答が登録済みの月報に対して再度回答を登録・上書きしようとした場合の扱い。
- 回答対象の月報が削除された場合、既存の回答表示はどう扱われるか。
- 回答入力欄に空文字のみを入力して公開しようとした場合の扱い。
- 回答期限（翌月5日）ちょうどの境界日時での可否判定。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは閲覧権限を持つユーザーに対し、月報の対象月・所属情報・営業情報・残業見込み（時間・理由）・コンディション7項目・コメントを詳細画面に表示しなければならない。
- **FR-002**: システムは月報詳細画面に回答内容（未登録の場合はその旨、登録済みの場合は内容・回答者ロール・氏名・回答日時）を表示しなければならない。
- **FR-003**: システムは月報の作成者本人にのみ編集ボタンを表示しなければならない。
- **FR-004**: システムは月報の作成者本人またはOMロールのユーザーにのみ削除ボタンを表示しなければならない。
- **FR-005**: システムはTL以上のロールを持ち、かつ自分以外が作成した月報を閲覧しているユーザーにのみ回答入力欄を表示しなければならない。
- **FR-006**: システムは自分自身が作成した月報に対する回答登録を、そのユーザーがどのロールであっても拒否しなければならない。
- **FR-007**: システムはTL未満のロール（TM/NG）のユーザーに対し、回答の登録を許可してはならない。
- **FR-008**: システムは回答が登録された際、回答者のロール・氏名・登録日時を記録し、全ロールに閲覧可能な形で表示しなければならない。
- **FR-009**: システムは報告月の翌月5日を過ぎた月報に対する回答登録を拒否しなければならない。

### Key Entities

- **月報**: 対象月・所属情報・営業情報・残業見込み・コンディション7項目・コメント・作成者・更新日時を持つ（作成・編集・削除の詳細は別仕様で定義）。
- **回答（フィードバック）**: 対象の月報に対して1件存在し、回答コメント・回答者のロール・回答者氏名・回答日時を持つ。TL以上のロールを持ち、かつ月報作成者本人ではないユーザーのみが登録できる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 閲覧権限を持つユーザーの100%が、月報を開いてから追加操作なしで全項目と回答状況を確認できる。
- **SC-002**: 編集・削除ボタンの表示可否が、権限ルール（作成者本人／OM）と100%一致する。
- **SC-003**: 回答入力欄の表示可否および回答登録の成否が、権限ルール（TL以上かつ他者の月報）と100%一致する。
- **SC-004**: 報告月の翌月5日を過ぎた月報への回答登録試行の100%が拒否される。

## Assumptions

- 月報の作成・編集・削除そのものの詳細フロー（入力項目のバリデーション等）は別機能（月報作成・編集・削除）で扱い、本仕様は詳細画面での表示・導線・回答機能のみを対象とする。
- 回答の再登録・上書き可否は本仕様では定義せず、既存の業務運用（初回登録のみ、または上書き可）に従う。
- 回答内容の文字数上限や必須/任意の扱いは、月報コメント項目に準じた妥当な制約を適用する前提とする。
