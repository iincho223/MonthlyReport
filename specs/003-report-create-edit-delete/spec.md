# Feature Specification: 月報作成・編集・削除

**Feature Branch**: `003-report-create-edit-delete`

**Created**: 2026-08-22

**Status**: Draft

**Input**: User description: "月報の作成・編集・削除機能。社員は対象月（yyyy-MM）、営業情報（任意）、来月残業見込み時間（0-300, 任意）と理由（最大255文字, 任意）、今月残業見込み時間（0-300, 任意）と理由（最大255文字, 任意）、コンディション自己診断7項目（体調・ストレス・人間関係・悩み・疲れ・睡眠・やる気を◎/○/▲/×の4段階で必須入力）、コメント（任意）を入力し月報を提出する。表示順は営業情報→来月残業見込み→今月残業見込み→コンディション7項目→コメントの順を維持する。同一ユーザーが同一月に複数の月報を作成することはできない。編集は作成者本人のみ可能。削除は作成者本人またはOMロールのみ可能で、削除は論理削除として扱う。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 月報を新規に作成・提出する (Priority: P1)

社員が対象月の月報を入力し、提出する。

**Why this priority**: 月報提出はシステムの根幹機能であり、これがなければ他の全機能（一覧・詳細・フィードバック・ダッシュボード集計）が成立しない。

**Independent Test**: 月報未提出のユーザーが必須項目を入力して提出し、月報が1件作成されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** 今月分を未提出のユーザーが月報作成画面を開いている、**When** コンディション自己診断7項目を含む必須項目を入力し提出する、**Then** 新しい月報が作成され、一覧・ダッシュボードに反映される。
2. **Given** 今月分を未提出のユーザーが月報作成画面を開いている、**When** コンディション自己診断7項目のいずれかを未入力のまま提出しようとする、**Then** システムは提出を許可せず、未入力項目を示す。
3. **Given** すでに今月分の月報を提出済みのユーザーが、**When** 同じ対象月で再度月報を新規作成しようとする、**Then** システムは重複作成を拒否する。
4. **Given** 月報作成画面を開いている、**When** 各入力項目を確認する、**Then** 営業情報→来月残業見込み（時間・理由）→今月残業見込み（時間・理由）→コンディション7項目→コメントの順で表示されている。

---

### User Story 2 - 提出済みの月報を編集する (Priority: P1)

作成者本人が、自分の提出済み月報の内容を修正する。

**Why this priority**: 提出後の内容修正は月報運用に不可欠であり、新規作成（P1）と並ぶ基本操作のため同等の優先度とする。

**Independent Test**: 作成者本人が自分の月報を開いて内容を変更し保存することで、変更が反映されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** 作成者本人が自分の月報を編集画面で開いている、**When** 内容を変更して保存する、**Then** 月報の内容が更新され、更新日時が更新される。
2. **Given** 作成者本人以外のユーザーが他人の月報を編集しようとする、**When** 更新を試みる、**Then** システムは更新を拒否する。

---

### User Story 3 - 不要な月報を削除する (Priority: P2)

作成者本人またはOMロールのユーザーが、月報を削除する。

**Why this priority**: 誤って作成した月報の取り消し等に必要だが、作成・編集（P1）に比べ利用頻度が低いため次点の優先度とする。

**Independent Test**: 作成者本人またはOMロールのユーザーが対象の月報を削除し、以降その月報が一覧・詳細から見えなくなることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** 作成者本人が自分の月報の削除を実行する、**When** 削除操作を行う、**Then** 月報は削除された状態になり、一覧・ダッシュボードから除外される。
2. **Given** OMロールのユーザーが他者の月報の削除を実行する、**When** 削除操作を行う、**Then** 月報は削除された状態になる。
3. **Given** 作成者本人でもOMロールでもないユーザーが他者の月報の削除を試みる、**When** 削除操作を行う、**Then** システムは削除を拒否する。
4. **Given** 削除済みの月報が存在する、**When** 削除済みデータの扱いを確認する、**Then** データは物理的に消去されず、参照不可な状態（論理削除）として保持される。

### Edge Cases

- 来月/今月残業見込み時間に0-300の範囲外の値を入力しようとした場合、システムは提出を許可しない。
- 残業理由に255文字を超える文字列を入力しようとした場合、システムは提出を許可しない。
- 対象月として未来の月・過去の月を指定した場合の扱い（本仕様では制限しない前提とするが、業務側で別途制約があれば従う）。
- 編集中に他の操作（ブラウザバック等）で未保存の変更が失われる可能性がある場合の扱い。
- 既に削除済みの月報に対して編集・再削除を試みた場合、システムは操作を拒否する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは対象月（年月）を必須項目として月報に含めなければならない。
- **FR-002**: システムはコンディション自己診断7項目（体調・ストレス・人間関係・悩み・疲れ・睡眠・やる気）を必須項目とし、各項目は4段階（◎/○/▲/×）のいずれかでなければならない。
- **FR-003**: システムは営業情報・来月残業見込み時間と理由・今月残業見込み時間と理由・コメントを任意項目として受け付けなければならない。
- **FR-004**: システムは残業見込み時間が0〜300の範囲外の場合、入力を拒否しなければならない。
- **FR-005**: システムは残業理由が255文字を超える場合、入力を拒否しなければならない。
- **FR-006**: システムは月報作成・編集画面において、営業情報→来月残業見込み→今月残業見込み→コンディション7項目→コメントの順で項目を表示しなければならない。
- **FR-007**: システムは同一ユーザー・同一対象月について、有効な月報を重複して作成することを禁止しなければならない。
- **FR-008**: システムは月報の編集を、その月報の作成者本人にのみ許可しなければならない。
- **FR-009**: システムは月報の削除を、作成者本人またはOMロールのユーザーにのみ許可しなければならない。
- **FR-010**: システムは月報の削除を論理削除として扱い、削除後は一覧・詳細・集計から除外しなければならない。
- **FR-011**: システムは削除済みの月報に対する編集・再削除の操作を拒否しなければならない。

### Key Entities

- **月報**: 作成者、対象月（年月、作成者ごとに一意）、営業情報、来月/今月の残業見込み時間・理由、コンディション自己診断7項目、コメント、作成日時、更新日時、削除状態（論理削除フラグ）を持つ。
- **コンディション自己診断項目**: 体調・ストレス・人間関係・悩み・疲れ・睡眠・やる気の7種で構成され、各項目は4段階（絶好調/普通/不調/最悪）のいずれかの値を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 必須項目を正しく入力したユーザーの100%が、月報の新規提出を完了できる。
- **SC-002**: 重複作成・範囲外入力・文字数超過を試みた操作の100%がシステムによって拒否され、不正なデータが保存されない。
- **SC-003**: 作成者本人による編集の100%が反映され、作成者本人以外による編集の100%が拒否される。
- **SC-004**: 削除権限を持つユーザーによる削除操作の100%が反映され、削除後の月報は一覧・ダッシュボードに表示されない。

## Assumptions

- 月報の閲覧（一覧・詳細表示）とフィードバック（TL以上による回答）は別機能として扱い、本仕様では作成・編集・削除のみを対象とする。
- 対象月として未来月・過去月を指定できるかどうかの制約は本仕様では定義せず、既存の業務運用に従う。
- 削除された月報データの保持期間・完全消去のポリシーは本仕様の対象外とする。
- コンディション項目の4段階表示（◎/○/▲/×）と内部値（絶好調/普通/不調/最悪の4区分）の対応関係は固定であり、変更は本仕様の対象外とする。
