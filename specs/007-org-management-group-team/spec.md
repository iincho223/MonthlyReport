# Feature Specification: 組織管理（グループ・チーム）

**Feature Branch**: `007-org-management-group-team`

**Created**: 2026-08-22

**Status**: Draft

**Input**: User description: "グループ・チームの一覧・登録・削除機能。GL/OM/SAのみアクセス可能で、それ以外のロールはアクセス不可。グループ一覧にはグループコード・グループ名・GL氏名を表示する。チーム一覧にはチームコード・チーム名・所属グループ・TL氏名を表示する。グループ登録時はGLへ指定するユーザーを必須とし、OM/SAのみグループの登録・削除ができる（GLはグループ自体の登録・削除は不可）。チーム登録時はTLへ指定するユーザーを必須とし、GLは自グループ配下のみ、OMは自営業所内全体、SAは全権限でチームを登録・削除できる。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 組織構成（グループ・チーム）の一覧を確認する (Priority: P1)

管理権限を持つユーザーが、自分の管理範囲のグループおよびチームの一覧を確認できる。

**Why this priority**: 登録・削除操作の前提として、まず現在の組織構成を把握する必要があり、本機能の基本操作である。

**Independent Test**: 管理権限を持つロールでログインし、グループ一覧・チーム一覧に表示される対象が業務仕様の管理範囲と一致することを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** GLロールでログインしている、**When** 組織管理画面を開く、**Then** 自グループのチームのみが一覧に表示される。
2. **Given** OMまたはSAロールでログインしている、**When** 組織管理画面を開く、**Then** OMは自営業所の全グループ・チーム、SAは全営業所の全グループ・チームが一覧に表示される。
3. **Given** NG・TM・TL・SP・SMいずれかのロールでログインしている、**When** 組織管理画面へのアクセスを試みる、**Then** システムはアクセスを許可しない。
4. **Given** グループ一覧が表示されている、**When** 各行を確認する、**Then** グループコード・グループ名・GL氏名が表示されている。
5. **Given** チーム一覧が表示されている、**When** 各行を確認する、**Then** チームコード・チーム名・所属グループ・TL氏名が表示されている。

---

### User Story 2 - グループを登録・削除する (Priority: P2)

OMまたはSAロールのユーザーが、新しいグループを登録し、または不要なグループを削除する。

**Why this priority**: グループの新設・廃止は組織変更時のみ発生する操作であり、日常的なチーム管理（後述）に比べて発生頻度が低いため、一覧確認に次ぐ優先度とする。

**Independent Test**: OMまたはSAロールのユーザーがGL氏名を指定してグループを登録し、一覧に反映されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** OMまたはSAロールでログインしている、**When** GLへ指定するユーザーを含めてグループを登録する、**Then** 新しいグループが作成され一覧に反映される。
2. **Given** OMまたはSAロールでログインしている、**When** GLへ指定するユーザーを指定せずにグループを登録しようとする、**Then** システムは登録を拒否する。
3. **Given** GLロールでログインしている、**When** グループの新規登録またはグループ自体の削除を試みる、**Then** システムはその操作を許可しない。
4. **Given** OMまたはSAロールでログインしている、**When** 既存のグループを削除する、**Then** グループが削除され一覧から除外される。

---

### User Story 3 - チームを登録・削除する (Priority: P1)

GL・OM・SAロールのユーザーが、自分の管理範囲内でチームを登録・削除する。

**Why this priority**: チームは日常的な人員配置の単位であり、グループ登録より発生頻度・業務上の重要度が高いと想定されるため、一覧確認と並ぶ優先度とする。

**Independent Test**: GL・OM・SAいずれかのロールのユーザーがTL氏名を指定してチームを登録し、一覧に反映されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** GLロールでログインしている、**When** 自グループ配下にTLへ指定するユーザーを含めてチームを登録する、**Then** 新しいチームが作成される。
2. **Given** GLロールでログインしている、**When** 自グループ以外の配下にチームを登録しようとする、**Then** システムは登録を拒否する。
3. **Given** OMロールでログインしている、**When** 自営業所内の任意のグループ配下にチームを登録する、**Then** チームが作成される。
4. **Given** SAロールでログインしている、**When** 任意のグループ配下にチームを登録する、**Then** チームが作成される。
5. **Given** GL・OM・SAいずれかのロールでログインしている、**When** TLへ指定するユーザーを指定せずにチームを登録しようとする、**Then** システムは登録を拒否する。
6. **Given** GL・OM・SAいずれかのロールでログインしている、**When** 自分の管理範囲内のチームを削除する、**Then** チームが削除され一覧から除外される。
7. **Given** GLロールでログインしている、**When** 自グループ以外のチームを削除しようとする、**Then** システムは削除を拒否する。

### Edge Cases

- グループ削除時に、そのグループ配下にチームが存在する場合の扱い（本仕様では削除可否の判断基準として定義しない）。
- チーム削除時に、そのチームに所属するメンバー（ユーザー）が存在する場合の扱い。
- 同じグループコード・チームコードで重複登録しようとした場合、システムは登録を拒否する。
- GLに指定するユーザー・TLに指定するユーザーが、実際には対象ロール（GL/TL）を持たないユーザーであった場合の扱い。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはGL・OM・SAロールのユーザーにのみ組織管理画面へのアクセスを許可しなければならない。
- **FR-002**: システムはNG・TM・TL・SP・SMロールのユーザーに対し、組織管理画面へのアクセスを拒否しなければならない。
- **FR-003**: システムはグループ一覧にグループコード・グループ名・GL氏名を表示しなければならない。
- **FR-004**: システムはチーム一覧にチームコード・チーム名・所属グループ・TL氏名を表示しなければならない。
- **FR-005**: システムはGLロールのユーザーに対し、自グループのチームのみを一覧表示・登録・削除の対象としなければならない。
- **FR-006**: システムはGLロールのユーザーによるグループ自体の登録・削除を拒否しなければならない。
- **FR-007**: システムはOMロールのユーザーに対し、自営業所内の全グループ・チームを一覧表示・登録・削除の対象としなければならない。
- **FR-008**: システムはSAロールのユーザーに対し、全営業所の全グループ・チームを一覧表示・登録・削除の対象としなければならない。
- **FR-009**: システムはグループ登録時、GLに指定するユーザーの指定を必須としなければならない。
- **FR-010**: システムはチーム登録時、TLに指定するユーザーの指定を必須としなければならない。
- **FR-011**: システムは各ロールの管理範囲を超えるグループ・チームの登録・削除要求を拒否しなければならない。

### Key Entities

- **グループ**: グループコード、グループ名、所属営業所、GL（グループリーダー）ユーザーを持つ。配下に複数のチームを持つ。
- **チーム**: チームコード、チーム名、所属グループ、TL（チームリーダー）ユーザーを持つ。配下に複数のメンバー（ユーザー）を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 各ロールで表示されるグループ・チーム件数が、業務仕様上の管理範囲定義と100%一致する。
- **SC-002**: 管理範囲内でのグループ・チーム登録試行の100%が成功し、管理範囲外への登録試行の100%が拒否される。
- **SC-003**: 管理範囲内でのグループ・チーム削除試行の100%が成功し、管理範囲外への削除試行の100%が拒否される。
- **SC-004**: GL指定なしのグループ登録、TL指定なしのチーム登録の試行の100%が拒否される。

## Assumptions

- グループ・チームの編集（名称変更、GL/TLの変更）機能は本仕様には含めず、登録・削除・一覧表示のみを対象とする。既存の業務仕様に編集操作の記載がないため対象外とする。
- 削除対象のグループ・チームに所属メンバーが存在する場合の連鎖的な扱い（メンバーの再配置等）は本仕様の対象外とする。
- グループコード・チームコードの一意性はシステムによって保証される前提とする。
