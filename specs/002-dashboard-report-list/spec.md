# Feature Specification: ダッシュボード・月報一覧

**Feature Branch**: `002-dashboard-report-list`

**Created**: 2026-08-22

**Status**: Draft

**Input**: User description: "ログイン後に表示されるダッシュボード（月報一覧）機能。全ロール共通で、今月の残日数と自分が今月分を提出済みかどうかを示す提出期限バナーをヘッダー直下に固定表示する。TL以上のロールには追加で、今月の提出完了率（進捗バー付き）と未提出メンバー一覧（全員提出済みなら完了メッセージ）を表示する。月報カード一覧は月降順で表示し、各カードに回答ステータス（Checked/Reviewing）バッジを表示する。表示される月報の範囲はロールによって異なる：NGはアクセス不可、TMは自分の月報のみ、TLは自分＋同一チーム、GLは自分＋同一グループ、OM/SMは営業所全件、SPは自分が担当となっている月報、SAは全件をマスク表示。締切日は毎月5日で、提出リマインドは前月25日から提出するまで（当月は毎日）行う。ユーザーは新規提出ボタンから月報作成画面へ遷移できる。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自分の提出状況を一目で確認する (Priority: P1)

ログインした社員が、今月の締切までの残日数と自分が提出済みかどうかを、画面を開いた瞬間に確認できる。

**Why this priority**: 提出期限の把握は全ロール共通で必要な最重要情報であり、これだけでも独立して価値がある（提出忘れの防止）。

**Independent Test**: 任意のロールでログインし、ダッシュボードを開いた際に提出期限バナーが残日数と自分の提出有無を表示することを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** 今月分を未提出のユーザーがログインしている、**When** ダッシュボードを開く、**Then** ヘッダー直下に今月の残日数と「未提出」を示す警告表示のバナーが固定表示される。
2. **Given** 今月分を提出済みのユーザーがログインしている、**When** ダッシュボードを開く、**Then** バナーは「提出済み」を示す完了表示に切り替わる。

---

### User Story 2 - 自分の可視範囲内の月報一覧を確認する (Priority: P1)

ユーザーが、自分のロールに応じて閲覧可能な範囲の月報一覧をカード形式で確認できる。

**Why this priority**: 月報の状況把握という本機能の中核価値であり、P1として提出期限バナーと並ぶ主要目的。

**Independent Test**: 各ロールでログインし、月報一覧に表示される件数・対象が業務仕様のロール別可視範囲と一致することを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** TMロールでログインしている、**When** ダッシュボードを開く、**Then** 自分が提出した月報のみが月降順のカード一覧に表示される。
2. **Given** TLロールでログインしている、**When** ダッシュボードを開く、**Then** 自分の月報と同一チームメンバーの月報がカード一覧に表示される。
3. **Given** GL/OM/SM/SPいずれかのロールでログインしている、**When** ダッシュボードを開く、**Then** 各ロールの業務仕様上の可視範囲（同一グループ／営業所全件／担当分）に応じた月報が表示される。
4. **Given** SAロールでログインしている、**When** ダッシュボードを開く、**Then** 月報一覧は表示されるが内容はマスクされた状態で表示される。
5. **Given** NGロールでログインしている、**When** ダッシュボードへのアクセスを試みる、**Then** システムはアクセスを許可しない。
6. **Given** 月報カードが表示されている、**When** 一覧を確認する、**Then** 各カードに回答ステータス（Checked=回答あり / Reviewing=回答待ち）バッジが表示される。

---

### User Story 3 - チーム・組織の提出状況を管理する (Priority: P2)

TL以上のロールを持つユーザーが、自分の管理範囲における今月の提出完了率と未提出者を確認できる。

**Why this priority**: 管理職ロール向けの付加価値であり、P1（個人の提出状況・一覧閲覧）が成立した上で意味を持つため次点の優先度とする。

**Independent Test**: TL以上のロールでログインし、提出完了率（進捗バー）と未提出メンバー一覧が表示されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** TL以上のロールでログインしている、**When** ダッシュボードを開く、**Then** 今月の提出完了率が進捗バー付きで表示される。
2. **Given** TL以上のロールでログインし、未提出メンバーが存在する、**When** ダッシュボードを開く、**Then** 未提出メンバーがチップ形式の一覧で表示される。
3. **Given** TL以上のロールでログインし、管理範囲内の全員が提出済みである、**When** ダッシュボードを開く、**Then** 未提出メンバー一覧の代わりに完了メッセージが表示される。
4. **Given** TM/NGロールでログインしている、**When** ダッシュボードを開く、**Then** 提出完了率・未提出メンバー一覧は表示されない。

---

### User Story 4 - 新規月報の提出画面へ遷移する (Priority: P3)

ユーザーがダッシュボードから新規提出ボタンを押し、月報作成画面へ遷移できる。

**Why this priority**: ダッシュボードから別機能（月報作成）への導線に過ぎず、他のユーザーストーリーが機能していなくても単独で検証できる小さな価値のため優先度は最も低い。

**Independent Test**: ダッシュボード上の新規提出ボタンを押し、月報作成画面へ遷移することを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** ダッシュボードを表示している、**When** 新規提出ボタンを押す、**Then** 月報作成画面へ遷移する。

### Edge Cases

- 締切日（毎月5日）を過ぎても未提出の場合、提出期限バナーの残日数表示・リマインドはどう扱われるか（マイナス日数表示か、締切超過の専用表示かは業務仕様側の詳細に従う）。
- 月報が1件も存在しない可視範囲のユーザーがダッシュボードを開いた場合、一覧は空状態を表示する。
- ロールの可視範囲に含まれるメンバーが0人（例: チーム未所属）の場合、提出完了率・未提出メンバー一覧の扱い。
- 月をまたぐタイミング（月初）でのリマインド・残日数表示の切り替え。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはNGロールに対してダッシュボードへのアクセスを許可してはならない。
- **FR-002**: システムは全ロール（NGを除く）に対し、今月の残日数と自分の今月分提出有無を示す提出期限バナーをヘッダー直下に固定表示しなければならない。
- **FR-003**: システムは自分が今月分を未提出の場合は警告表示、提出済みの場合は完了表示にバナーを切り替えなければならない。
- **FR-004**: システムはユーザーのロールに応じて月報一覧の可視範囲を制御しなければならない（TM: 自分のみ／TL: 自分+同一チーム／GL: 自分+同一グループ／OM・SM: 営業所全件／SP: 自分が担当となっている月報／SA: 全件マスク表示）。
- **FR-005**: システムは月報一覧を月（year-month）の降順で表示しなければならない。
- **FR-006**: システムは各月報カードに回答ステータス（Checked=回答あり／Reviewing=回答待ち）を表示しなければならない。
- **FR-007**: システムはTL以上のロールに対し、今月の提出完了率を進捗バーとともに表示しなければならない。
- **FR-008**: システムはTL以上のロールに対し、今月の未提出メンバーをチップ形式で表示しなければならない。全員提出済みの場合は完了メッセージを表示しなければならない。
- **FR-009**: システムはTM/NGロールに対し、提出完了率および未提出メンバー一覧を表示してはならない。
- **FR-010**: システムは新規提出ボタンから月報作成画面へ遷移する手段を提供しなければならない。
- **FR-011**: システムは締切日（毎月5日）を基準として提出期限の残日数を算出しなければならない。
- **FR-012**: システムは未提出のユーザーに対し、報告月の前月25日から提出完了まで毎日リマインドを行わなければならない。

### Key Entities

- **月報**: 対象月（YYYY-MM）、作成者、所属チーム/グループ/営業所、回答登録状況（Checked/Reviewing）、更新日時を持つ。1ユーザー・1対象月につき1件のみ存在する。
- **提出状況集計**: 対象月における総提出件数、未回答件数、提出完了率、未提出メンバー一覧からなる。ロール（TL以上か否か）によって参照可否が変わる。
- **ユーザー（社員）**: ロール・所属チーム・所属グループ・所属営業所を持ち、月報一覧の可視範囲・提出状況集計の参照可否を決定する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーがダッシュボードを開いてから提出期限バナー（残日数・自分の提出有無）が表示されるまで2秒以内で完了する。
- **SC-002**: 各ロールで表示される月報件数が、業務仕様上の可視範囲定義と100%一致する。
- **SC-003**: TL以上のユーザーの100%が、追加操作なしで今月の提出完了率と未提出メンバーを確認できる。
- **SC-004**: 未提出ユーザーへのリマインドが、報告月の前月25日から提出完了まで毎日欠落なく行われる。

## Assumptions

- 提出期限バナーの「残日数」は締切日（毎月5日）を基準に算出し、締切超過後の具体的な表示文言は本仕様では定義しない（別途詳細化する）。
- リマインドの配信手段（画面内通知/メール等）は本仕様の対象外とし、リマインド「が行われるべきタイミング」のみを対象とする。
- 月報の新規作成・編集・削除そのものの詳細仕様は別機能（月報作成・編集・削除）で扱い、本機能では一覧・集計・遷移導線のみを対象とする。
- ページング・検索条件（ステータス絞り込み等）の詳細UIは本仕様の対象外とし、月降順の一覧表示と可視範囲制御を主眼とする。
