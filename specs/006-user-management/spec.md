# Feature Specification: ユーザー管理

**Feature Branch**: `006-user-management`

**Created**: 2026-08-22

**Status**: Draft

**Input**: User description: "ユーザー（社員）の一覧・登録・削除機能。GL/OM/SP/SM/SAのみアクセス可能で、NG/TM/TLはアクセス不可。一覧には社員番号・氏名・ロール表示名・営業所・チームを表示する。登録・削除できる範囲はロールで異なる：GLは自グループおよび配下チームへのエンジニア登録・削除のみ、OMは自営業所の全グループ・チームへのエンジニア登録・削除、SP/SMは所属営業所のエンジニア・SP・SMユーザーの登録・削除、SAは全ユーザーの登録・削除が可能。自分自身のアカウントは削除できない。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理範囲内のユーザー一覧を確認する (Priority: P1)

管理権限を持つユーザーが、自分の管理範囲に含まれる社員の一覧を確認できる。

**Why this priority**: 登録・削除操作を行う前提として、まず対象範囲のユーザーを把握できる必要があり、本機能の基本操作である。

**Independent Test**: 管理権限を持つロールでログインし、ユーザー一覧に表示される件数・対象が業務仕様のロール別管理範囲と一致することを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** GLロールでログインしている、**When** ユーザー管理画面を開く、**Then** 自グループおよび配下チームのエンジニアのみが一覧に表示される。
2. **Given** OMロールでログインしている、**When** ユーザー管理画面を開く、**Then** 自営業所全体のユーザーが一覧に表示される。
3. **Given** SPまたはSMロールでログインしている、**When** ユーザー管理画面を開く、**Then** 所属営業所のエンジニア・SP・SMロールのユーザーが一覧に表示される。
4. **Given** SAロールでログインしている、**When** ユーザー管理画面を開く、**Then** 全ユーザーが一覧に表示される。
5. **Given** NG・TM・TLいずれかのロールでログインしている、**When** ユーザー管理画面へのアクセスを試みる、**Then** システムはアクセスを許可しない。
6. **Given** 一覧が表示されている、**When** 各行を確認する、**Then** 社員番号・氏名・ロール（表示名）・営業所・チームが表示されている。

---

### User Story 2 - 管理範囲内に新しいユーザーを登録する (Priority: P1)

管理権限を持つユーザーが、自分の管理範囲に新しい社員アカウントを登録する。

**Why this priority**: 新規社員の追加は組織運営に不可欠な操作であり、一覧確認（P1）と並ぶ本機能の中核目的とする。

**Independent Test**: 管理権限を持つユーザーが登録可能な範囲内でユーザーを1件登録し、一覧に反映されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** GLロールでログインしている、**When** 自グループまたは配下チームへエンジニアを登録する、**Then** ユーザーが登録され一覧に反映される。
2. **Given** GLロールでログインしている、**When** 自グループ・配下チーム以外の範囲へユーザーを登録しようとする、**Then** システムは登録を拒否する。
3. **Given** OMロールでログインしている、**When** 自営業所内の任意のグループ・チームへエンジニアを登録する、**Then** ユーザーが登録される。
4. **Given** SPまたはSMロールでログインしている、**When** 所属営業所にエンジニア・SP・SMロールのいずれかとしてユーザーを登録する、**Then** ユーザーが登録される。
5. **Given** SPまたはSMロールでログインしている、**When** 所属営業所外へ、またはエンジニア・SP・SM以外のロールでユーザーを登録しようとする、**Then** システムは登録を拒否する。
6. **Given** SAロールでログインしている、**When** 任意の営業所・ロールでユーザーを登録する、**Then** ユーザーが登録される。

---

### User Story 3 - 不要になったユーザーを削除する (Priority: P2)

管理権限を持つユーザーが、自分の管理範囲内のユーザーアカウントを削除する。

**Why this priority**: 登録（P1）に対する取り消し操作であり、利用頻度は登録より低いと想定されるため次点の優先度とする。

**Independent Test**: 管理権限を持つユーザーが削除可能な範囲内のユーザーを1件削除し、一覧から除外されることを確認するだけで完結してテストできる。

**Acceptance Scenarios**:

1. **Given** 削除権限を持つユーザーが自分の管理範囲内の他者ユーザーの削除ボタンを押す、**When** 削除を実行する、**Then** 対象ユーザーが削除され一覧から除外される。
2. **Given** 削除権限を持つユーザーが自分自身の行の削除ボタンを確認する、**When** 一覧を確認する、**Then** 自分自身の削除ボタンは無効化されている。
3. **Given** 削除権限を持つユーザーが、**When** 自分自身のアカウント削除を直接実行しようとする、**Then** システムは削除を拒否する。
4. **Given** 管理範囲外のユーザーに対し、**When** 削除を試みる、**Then** システムは削除を拒否する。

### Edge Cases

- 登録しようとした社員番号が既存ユーザーと重複していた場合、システムは登録を拒否する。
- GLロールで、GLに割り当てられているグループが存在しない状態でユーザー登録を試みた場合の扱い。
- SP/SMロールがエンジニア以外の登録可能ロール（SP・SM自身）で登録する際、登録先の営業所は自分の所属営業所に固定される。
- 削除対象のユーザーが月報やエスカレーションのデータを持つ場合の扱い（本仕様では削除可否の判断基準として扱わない）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはGL・OM・SP・SM・SAロールのユーザーにのみユーザー管理画面へのアクセスを許可しなければならない。
- **FR-002**: システムはNG・TM・TLロールのユーザーに対し、ユーザー管理画面へのアクセスを拒否しなければならない。
- **FR-003**: システムはユーザー一覧に社員番号・氏名・ロール（表示名）・営業所・チームを表示しなければならない。
- **FR-004**: システムはGLロールのユーザーに対し、自グループおよび配下チームのエンジニアのみを表示・登録・削除の対象としなければならない。
- **FR-005**: システムはOMロールのユーザーに対し、自営業所全体のユーザーを表示・登録・削除の対象としなければならない。
- **FR-006**: システムはSP・SMロールのユーザーに対し、所属営業所のエンジニア・SP・SMロールのユーザーのみを表示・登録・削除の対象としなければならない。
- **FR-007**: システムはSAロールのユーザーに対し、全ユーザーを表示・登録・削除の対象としなければならない。
- **FR-008**: システムは各ロールの登録可能範囲・ロールを超えるユーザー登録要求を拒否しなければならない。
- **FR-009**: システムは各ロールの管理範囲を超えるユーザー削除要求を拒否しなければならない。
- **FR-010**: システムはログイン中のユーザー自身のアカウント削除を、いかなるロールであっても拒否しなければならない。
- **FR-011**: システムはユーザー一覧において、自分自身の行の削除操作を無効化しなければならない。

### Key Entities

- **ユーザー（社員）**: 社員番号、氏名、ロール、所属営業所、所属チームを持つ。登録・削除の可否は、操作者のロールと、対象ユーザーの所属・ロールの組み合わせによって決まる。
- **管理範囲**: 操作者のロールに応じて定義される、登録・削除・閲覧が可能なユーザーの範囲（グループ／営業所／ロール制限）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 各ロールで表示されるユーザー件数が、業務仕様上の管理範囲定義と100%一致する。
- **SC-002**: 管理範囲内でのユーザー登録試行の100%が成功し、管理範囲外への登録試行の100%が拒否される。
- **SC-003**: 管理範囲内でのユーザー削除試行の100%が成功し、管理範囲外への削除試行の100%が拒否される。
- **SC-004**: 自分自身のアカウントに対する削除試行の100%が拒否される。

## Assumptions

- ユーザーの編集（ロール変更・所属変更等）機能は本仕様には含めず、登録・削除・一覧表示のみを対象とする。既存の業務仕様に編集操作の記載がないため対象外とする。
- 登録時の初期パスワード設定・パスワード再発行の詳細フローは本仕様の対象外とする。
- 社員番号の一意性はシステムによって保証される前提とする。
