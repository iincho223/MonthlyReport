## 1 基本情報

- API ID: API-02
- 名称: トークン再発行
- Method/URI: `POST /api/v1/auth/refresh`
- 認証: 不要
- アクセス可能ロール: **全員**（リフレッシュトークン所持者）

## 2 概要

有効なリフレッシュトークンを使ってアクセストークンとリフレッシュトークンを再発行する。

## 3 前提条件

- 有効なリフレッシュトークンを所持していること。

## 4 入出力仕様

### 4.1 Request

```json
{
  "refreshToken": "jwt..."
}
```

### 4.2 Request バリデーション

| 項目 | 必須 | ルール |
|---|---|---|
| refreshToken | 必須 | - |

### 4.3 Response(params)

```json
{
  "accessToken": "jwt...",
  "refreshToken": "jwt...",
  "expiresIn": 3600
}
```

## 5 ロジックフロー

1. `refresh_tokens` テーブルをトークンハッシュで照合する。
2. トークン存在チェックを行う。
   - 存在しない場合は、以下の処理を実行する。
     - `AUTH_002` を返す。
   - 存在する場合は、以下の処理を実行する。
     - 次のステップに進む。
3. `delete_flag=0` かつ `revoked_at is null` を確認する。
   - 失効済みの場合は、以下の処理を実行する。
     - `AUTH_002` を返す。
   - 有効な場合は、以下の処理を実行する。
     - 次のステップに進む。
4. 有効期限を確認する。
   - 期限切れの場合は、以下の処理を実行する。
     - `AUTH_003` を返す。
   - 有効期限内の場合は、以下の処理を実行する。
     - 次のステップに進む。
5. 新しいトークンペアを発行する。
6. 旧トークンを `revoked_at` を設定して失効させる。
7. 新しいトークンペアを返却する。

## 6 例外ケース

| ケース | エラーコード | 説明 |
|---|---|---|
| トークン無効 | `AUTH_002` | リフレッシュトークンが無効です |
| トークン期限切れ | `AUTH_003` | リフレッシュトークンの有効期限が切れています |
| システムエラー | `SYS_500` | システムエラーが発生しました |

| refresh_tokens | SELECT / UPDATE（失効） / INSERT（新規） |
