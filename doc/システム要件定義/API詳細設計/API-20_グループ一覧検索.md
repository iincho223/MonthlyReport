## 1 基本情報

- API ID: API-20
- 名称: グループ一覧検索
- Method/URI: `POST /api/v1/groups/search`
- 認証: 必須
- アクセス可能ロール: **GL・OM・SA のみ**（それ以外は 403）

## 2 概要

グループ一覧を検索して返却する。ロールに応じた表示スコープをサーバーで強制する。

## 3 前提条件

- 認証済み JWT が有効であること。
- ログインユーザーのロールが GL・OM・SA いずれかであること。

## 4 入出力仕様

### 4.1 Request

```json
{
  "officeCode": "TOKYO",
  "groupName": "",
  "page": 1,
  "size": 20
}
```

### 4.2 Request バリデーション

| 項目 | 必須 | ルール |
|---|---|---|
| officeCode | 任意 | - |
| groupName | 任意 | 部分一致検索 |
| page | 任意 | デフォルト 1 |
| size | 任意 | デフォルト 20、最大 100 |

### 4.3 Response(params)

```json
{
  "groups": [
    {
      "groupCode": "GROUP_A",
      "groupName": "東京第1グループ",
      "officeCode": "TOKYO",
      "officeName": "東京営業所",
      "glUserId": 1001,
      "glUserName": "田中 太郎",
      "teamCount": 3,
      "memberCount": 12
    }
  ],
  "totalCount": 5,
  "page": 1,
  "size": 20
}
```

## 5 ロジックフロー

1. JWT からログインユーザーのロール/所属を取得する。
2. ロールを確認する。
   - GL・OM・SA 以外の場合は、以下の処理を実行する。
     - `AUTH_403` を返す。
   - GL・OM・SA の場合は、以下の処理を実行する。
     - 次のステップに進む。
3. ロール別スコープを決定する。
   - GL の場合は、以下の処理を実行する。
     - 自グループのみを対象とする。
   - OM の場合は、以下の処理を実行する。
     - 自営業所配下の全グループを対象とする。
   - SA の場合は、以下の処理を実行する。
     - 全グループを対象とする。
4. Request のフィールドでフィルタリングする（groupName は部分一致）。
5. ページネーションを適用する。
6. グループ情報（GL 名・チーム数・メンバー数含む）を組み立てて返却する。

## 6 例外ケース

| ケース | エラーコード | 説明 |
|---|---|---|
| 未認証 | `AUTH_001` | ログインしてください |
| 権限不足 | `AUTH_403` | 権限がありません |
