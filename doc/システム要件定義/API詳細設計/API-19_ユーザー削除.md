## 1 基本情報

- API ID: API-19
- 名称: ユーザー削除
- Method/URI: `POST /api/v1/users/delete`
- 認証: 必須
- アクセス可能ロール: **GL・OM・SP・SM・SA のみ**（それ以外は 403）

## 2 概要

指定したユーザーを削除する。自分自身のアカウントは削除できない。

## 3 前提条件

- 認証済み JWT が有効であること。
- ログインユーザーのロールが GL 以上（SP/SM/SA 含む）であること。

## 4 入出力仕様

### 4.1 Request

```json
{
  "userId": 1005
}
```

### 4.2 Request バリデーション

| 項目 | 必須 | ルール |
|---|---|---|
| userId | 必須 | 数値 |

### 4.3 Response(params)

```json
{
  "deleted": true,
  "userId": 1005
}
```

## 5 ロジックフロー

1. JWT からログインユーザーのロール/所属を取得する。
2. ロールを確認する。
   - GL/OM/SP/SM/SA 以外の場合は、以下の処理を実行する。
     - `AUTH_403` を返す。
   - GL/OM/SP/SM/SA の場合は、以下の処理を実行する。
     - 次のステップに進む。
3. 削除対象ユーザーが存在するか確認する。
   - 存在しない場合は、以下の処理を実行する。
     - `USER_404` を返す。
   - 存在する場合は、以下の処理を実行する。
     - 次のステップに進む。
4. 削除対象がログインユーザー自身かを確認する。
   - 自分自身の場合は、以下の処理を実行する。
     - `USER_400` を返す。
   - 自分自身ではない場合は、以下の処理を実行する。
     - 次のステップに進む。
5. ロール別スコープを確認する。
   - GL の場合は、以下の処理を実行する。
     - 削除対象が自グループ配下の NG/TM（エンジニア）であることを確認する。
   - OM の場合は、以下の処理を実行する。
     - 削除対象が自営業所配下の NG/TM（エンジニア）であることを確認する。
   - SP/SM の場合は、以下の処理を実行する。
     - 削除対象が自営業所配下の NG/TM/SP/SM であることを確認する。
   - SA の場合は、以下の処理を実行する。
     - 全スコープを許可する。
6. スコープ外の場合は、以下の処理を実行する。
   - `AUTH_403` を返す。
7. `users` テーブルから DELETE（または論理削除）する。
8. `deleted: true` と `userId` を返却する。

## 6 例外ケース

| ケース | エラーコード | 説明 |
|---|---|---|
| 未認証 | `AUTH_001` | ログインしてください |
| 権限不足 | `AUTH_403` | 権限がありません |
| ユーザー未存在 | `USER_404` | ユーザーが存在しません |
| 自分自身削除 | `USER_400` | 自分自身は削除できません |

## 7 CRUD

| テーブル | 操作 |
|---|---|
| users | SELECT（検索・スコープ確認） / DELETE |
