## 1 基本情報

- API ID: API-21
- 名称: グループ登録
- Method/URI: `POST /api/v1/groups/create`
- 認証: 必須
- アクセス可能ロール: **OM・SA のみ**（GL は作成不可、それ以外は 403）

## 2 概要

グループを新規登録する。グループ登録時は GL となるユーザーの指定が必須。

## 3 前提条件

- 認証済み JWT が有効であること。
- ログインユーザーのロールが OM または SA であること。

## 4 入出力仕様

### 4.1 Request

```json
{
  "groupCode": "GROUP_B",
  "groupName": "東京第2グループ",
  "officeCode": "TOKYO",
  "glUserId": 1008
}
```

### 4.2 Request バリデーション

| 項目 | 必須 | ルール |
|---|---|---|
| groupCode | 必須 | 英数字アンダースコア、最大32文字、一意 |
| groupName | 必須 | 最大100文字 |
| officeCode | 必須 | 既存営業所コード |
| glUserId | 必須 | GL に指定するユーザーの ID |

### 4.3 Response(params)

```json
{
  "groupCode": "GROUP_B",
  "groupName": "東京第2グループ"
}
```

## 5 ロジックフロー

1. JWT からログインユーザーのロール/所属を取得する。
2. ロールを確認する。
   - OM・SA 以外の場合は、以下の処理を実行する。
     - `AUTH_403` を返す。
   - OM・SA の場合は、以下の処理を実行する。
     - 次のステップに進む。
3. OM の場合は、以下の処理を実行する。
   - 指定 `officeCode` が自営業所であることを確認する。
   - スコープ外の場合は `AUTH_403` を返す。
4. `glUserId` のユーザーが存在するか確認する。
   - 存在しない場合は、以下の処理を実行する。
     - `USER_404` を返す。
   - 存在する場合は、以下の処理を実行する。
     - 次のステップに進む。
5. `groupCode` の重複チェックを行う。
   - 重複する場合は、以下の処理を実行する。
     - `GROUP_409` を返す。
   - 重複しない場合は、以下の処理を実行する。
     - 次のステップに進む。
6. `groups` テーブルに INSERT する。
7. `glUserId` のユーザーのロールを GL に更新する。
8. 登録した `groupCode` と `groupName` を返却する。

## 6 例外ケース

| ケース | エラーコード | 説明 |
|---|---|---|
| 未認証 | `AUTH_001` | ログインしてください |
| 権限不足 | `AUTH_403` | 権限がありません |
| GL ユーザー未存在 | `USER_404` | ユーザーが存在しません |
| グループコード重複 | `GROUP_409` | 同じグループコードが存在します |
| 入力不正 | `VAL_001` | 入力値を確認してください |

## 7 CRUD

| テーブル | 操作 |
|---|---|
| groups | SELECT（重複確認） / INSERT |
| users | SELECT（GL ユーザー確認） / UPDATE（ロール更新） |
