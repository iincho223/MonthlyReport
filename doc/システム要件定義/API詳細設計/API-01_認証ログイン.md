## 1 基本情報

- API ID: API-01
- 名称: 認証ログイン
- Method/URI: `POST /api/v1/auth/login`
- 認証: 不要
- アクセス可能ロール: **全員**（未認証ユーザーを含む）

## 2 概要

社員番号とパスワードを認証し、アクセストークンとリフレッシュトークンを返却する。

## 3 前提条件

- リクエスト元が有効な社員番号を所持していること。

## 4 入出力仕様

### 4.1 Request

```json
{
  "employeeNo": "EMP004",
  "password": "pass"
}
```

### 4.2 Request バリデーション

| 項目 | 必須 | ルール |
|---|---|---|
| employeeNo | 必須 | 英数字、最大20文字 |
| password | 必須 | 最大128文字 |

### 4.3 Response(params)

```json
{
  "accessToken": "jwt...",
  "refreshToken": "jwt...",
  "expiresIn": 3600,
  "userProfile": {
    "userId": 1004,
    "employeeNo": "EMP004",
    "name": "山田 健太",
    "role": "TM",
    "officeCode": "TOKYO",
    "teamCode": "TEAM_A"
  }
}
```

## 5 ロジックフロー

1. `users` テーブルを `employee_no` で検索する。
2. ユーザー存在チェックを行う。
   - 該当ユーザーが存在しない場合は、以下の処理を実行する。
     - `AUTH_001` を返す。
   - ユーザーが存在する場合は、以下の処理を実行する。
     - 次のステップに進む。
3. `delete_flag=0` かつ `is_active=1` を確認する。
   - 無効ユーザーの場合は、以下の処理を実行する。
     - `AUTH_001` を返す。
   - 有効ユーザーの場合は、以下の処理を実行する。
     - 次のステップに進む。
4. パスワードハッシュを照合する。
   - 不一致の場合は、以下の処理を実行する。
     - `AUTH_001` を返す。
   - 一致した場合は、以下の処理を実行する。
     - 次のステップに進む。
5. JWT（アクセストークン・リフレッシュトークン）を発行する。
6. `refresh_tokens` テーブルにリフレッシュトークンを登録する。
7. トークンとユーザープロフィールを返却する。

## 6 例外ケース

| ケース | エラーコード | 説明 |
|---|---|---|
| 認証失敗 | `AUTH_001` | 社員番号またはパスワードが正しくありません |
| 入力不正 | `VAL_001` | 入力値を確認してください |
| システムエラー | `SYS_500` | システムエラーが発生しました |

## 7 CRUD

| テーブル | 操作 |
|---|---|
| users | SELECT |
| refresh_tokens | INSERT |
