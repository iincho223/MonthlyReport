## 1 基本情報

- API ID: API-17
- 名称: ユーザー一覧検索
- Method/URI: `POST /api/v1/users/search`
- 認証: 必須
- アクセス可能ロール: **GL・OM・SP・SM・SA のみ**（それ以外は 403）

## 2 概要

ユーザー一覧をページング付きで返却する。
ロールに応じた参照スコープをサーバーで強制し、クライアントからの上書きを許可しない。

## 3 前提条件

- 認証済み JWT が有効であること。
- ログインユーザーのロールが GL 以上（SP/SM/SA 含む）であること。

## 4 入出力仕様

### 4.1 Request

```json
{
  "role": "TM",
  "officeCode": "TOKYO",
  "page": 1,
  "size": 20
}
```

### 4.2 Request バリデーション

| 項目 | 必須 | ルール |
|---|---|---|
| role | 任意 | ロール列挙値のみ（未指定時は全ロール） |
| officeCode | 任意 | - |
| page | 任意 | 1以上（省略時 1） |
| size | 任意 | 1-100（省略時 20） |

### 4.3 Response(params)

```json
{
  "items": [
    {
      "userId": 1004,
      "employeeNo": "EMP004",
      "name": "山田 健太",
      "role": "TM",
      "officeCode": "TOKYO",
      "teamCode": "TEAM_A"
    }
  ],
  "paging": {
    "page": 1,
    "size": 20,
    "totalElements": 1,
    "totalPages": 1
  }
}
```

## 5 ロジックフロー

1. JWT からログインユーザーのロール/所属を取得する。
2. ロールを確認する。
   - GL/OM/SP/SM/SA 以外の場合は、以下の処理を実行する。
     - `AUTH_403` を返す。
   - GL/OM/SP/SM/SA の場合は、以下の処理を実行する。
     - 次のステップに進む。
3. ロール別参照スコープ条件を組み立てる。
   - GL の場合は、以下の処理を実行する。
     - 自グループおよび配下チームのメンバー（エンジニア: NG/TM のみ）に絞る。
   - OM の場合は、以下の処理を実行する。
     - 自営業所の全ユーザーに絞る。
   - SP/SM の場合は、以下の処理を実行する。
     - 所属営業所のエンジニア・SP・SM に絞る。
   - SA の場合は、以下の処理を実行する。
     - 全ユーザーを対象とする。
4. リクエストのフィルター条件（role/officeCode）を付与する。
5. `users` テーブルから検索しページング結果を返す。

## 6 例外ケース

| ケース | エラーコード | 説明 |
|---|---|---|
| 未認証 | `AUTH_001` | ログインしてください |
| 権限不足 | `AUTH_403` | 権限がありません |
| 入力不正 | `VAL_001` | 入力値を確認してください |
