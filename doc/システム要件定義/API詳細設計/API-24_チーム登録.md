## 1 基本情報

- API ID: API-24
- 名称: チーム登録
- Method/URI: `POST /api/v1/teams/create`
- 認証: 必須
- アクセス可能ロール: **GL・OM・SA のみ**（それ以外は 403）

## 2 概要

チームを新規登録する。チーム登録時は TL となるユーザーの指定が必須。

## 3 前提条件

- 認証済み JWT が有効であること。
- ログインユーザーのロールが GL・OM・SA いずれかであること。

## 4 入出力仕様

### 4.1 Request

```json
{
  "teamCode": "TEAM_D",
  "teamName": "Dチーム",
  "groupCode": "GROUP_A",
  "tlUserId": 1006
}
```

### 4.2 Request バリデーション

| 項目 | 必須 | ルール |
|---|---|---|
| teamCode | 必須 | 英数字アンダースコア、最大32文字、一意 |
| teamName | 必須 | 最大100文字 |
| groupCode | 必須 | 既存グループコード |
| tlUserId | 必須 | TL に指定するユーザーの ID |

### 4.3 Response(params)

```json
{
  "teamCode": "TEAM_D",
  "teamName": "Dチーム"
}
```

## 5 ロジックフロー

1. JWT からログインユーザーのロール/所属を取得する。
2. ロールを確認する。
   - GL・OM・SA 以外の場合は、以下の処理を実行する。
     - `AUTH_403` を返す。
   - GL・OM・SA の場合は、以下の処理を実行する。
     - 次のステップに進む。
3. ロール別スコープを確認する。
   - GL の場合は、以下の処理を実行する。
     - 指定 `groupCode` が自グループであることを確認する。
   - OM の場合は、以下の処理を実行する。
     - 指定 `groupCode` が自営業所配下であることを確認する。
   - SA の場合は、以下の処理を実行する。
     - 全スコープを許可する。
4. スコープ外の場合は、以下の処理を実行する。
   - `AUTH_403` を返す。
5. `tlUserId` のユーザーが存在するか確認する。
   - 存在しない場合は、以下の処理を実行する。
     - `USER_404` を返す。
   - 存在する場合は、以下の処理を実行する。
     - 次のステップに進む。
6. `teamCode` の重複チェックを行う。
   - 重複する場合は、以下の処理を実行する。
     - `TEAM_409` を返す。
   - 重複しない場合は、以下の処理を実行する。
     - 次のステップに進む。
7. `teams` テーブルに INSERT する。
8. `tlUserId` のユーザーのロールを TL に更新する。
9. 登録した `teamCode` と `teamName` を返却する。

## 6 例外ケース

| ケース | エラーコード | 説明 |
|---|---|---|
| 未認証 | `AUTH_001` | ログインしてください |
| 権限不足 | `AUTH_403` | 権限がありません |
| TL ユーザー未存在 | `USER_404` | ユーザーが存在しません |
| チームコード重複 | `TEAM_409` | 同じチームコードが存在します |
| 入力不正 | `VAL_001` | 入力値を確認してください |

## 7 CRUD

| テーブル | 操作 |
|---|---|
| teams | SELECT（重複確認） / INSERT |
| users | SELECT（TL ユーザー確認） / UPDATE（ロール更新） |
| groups | SELECT（スコープ確認） |
