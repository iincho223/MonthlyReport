## 1 基本情報

- API ID: API-18
- 名称: ユーザー登録
- Method/URI: `POST /api/v1/users/create`
- 認証: 必須
- アクセス可能ロール: **GL・OM・SP・SM・SA のみ**（それ以外は 403）

## 2 概要

新規ユーザーを登録する。ロールに応じた登録可能スコープをサーバーで強制する。

## 3 前提条件

- 認証済み JWT が有効であること。
- ログインユーザーのロールが GL 以上（SP/SM/SA 含む）であること。

## 4 入出力仕様

### 4.1 Request

```json
{
  "employeeNo": "EMP010",
  "name": "新規 ユーザー",
  "role": "TM",
  "officeCode": "TOKYO",
  "teamCode": "TEAM_A",
  "password": "initialPass"
}
```

### 4.2 Request バリデーション

| 項目 | 必須 | ルール |
|---|---|---|
| employeeNo | 必須 | 英数字、最大20文字、一意 |
| name | 必須 | - |
| role | 必須 | ロール列挙値のみ |
| officeCode | 必須 | - |
| teamCode | 任意 | エンジニア（NG/TM）の場合は必須 |
| password | 必須 | 最大128文字 |

### 4.3 Response(params)

```json
{
  "userId": 1010,
  "employeeNo": "EMP010"
}
```

## 5 ロジックフロー

1. JWT からログインユーザーのロール/所属を取得する。
2. ロールを確認する。
   - GL/OM/SP/SM/SA 以外の場合は、以下の処理を実行する。
     - `AUTH_403` を返す。
   - GL/OM/SP/SM/SA の場合は、以下の処理を実行する。
     - 次のステップに進む。
3. 登録権限を確認する。
   - GL の場合は、以下の処理を実行する。
     - 登録可能ロールが NG/TM（エンジニア）のみであること、かつ指定チームが自グループ配下であることを確認する。
   - OM の場合は、以下の処理を実行する。
     - 登録可能ロールが NG/TM（エンジニア）のみであること、かつ指定営業所が自営業所であることを確認する。
   - SP/SM の場合は、以下の処理を実行する。
     - 登録可能ロールが NG/TM/SP/SM のみであること、かつ指定営業所が自営業所であることを確認する。
   - SA の場合は、以下の処理を実行する。
     - 全スコープを許可する。
4. スコープ外への登録の場合は、以下の処理を実行する。
   - `AUTH_403` を返す。
5. `employeeNo` の重複チェックを行う。
   - 重複する場合は、以下の処理を実行する。
     - `USER_409` を返す。
   - 重複しない場合は、以下の処理を実行する。
     - 次のステップに進む。
6. パスワードをハッシュ化する。
7. `users` テーブルに INSERT する。
8. 生成した `userId` と `employeeNo` を返却する。

## 6 例外ケース

| ケース | エラーコード | 説明 |
|---|---|---|
| 未認証 | `AUTH_001` | ログインしてください |
| 権限不足 | `AUTH_403` | 権限がありません |
| 社員番号重複 | `USER_409` | 同じ社員番号が存在します |
| 入力不正 | `VAL_001` | 入力値を確認してください |
